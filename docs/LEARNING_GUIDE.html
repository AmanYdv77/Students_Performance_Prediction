Models & Relational DB

1. Relational Database Schema & Authentication

Our database schema is separated into two apps: accounts (for users & roles) and academics (for colleges, subjects, results, and student profiles).

A. User Authentication & Role Customization

File path: app/accounts/models.py

Django provides a default user model, but to support VC, Dean, HOD, Teacher, and Student roles, we override it with a custom User model inherited from AbstractUser:

class User(AbstractUser):
    class Role(models.TextChoices):
        VC = "VC", "Vice Chancellor"
        REGISTRAR = "REGISTRAR", "Registrar"
        DEAN = "DEAN", "Dean"
        HOD = "HOD", "Head of Department"
        TEACHER = "TEACHER", "Teacher"
        STUDENT = "STUDENT", "Student"

    role = models.CharField(
        max_length=30,
        choices=Role.choices,
        default=Role.STUDENT,
        help_text="Decides what this user is allowed to see."
    )
    
    # Scope foreign keys for hierarchy tracking
    department = models.ForeignKey("academics.Department", on_delete=models.SET_NULL, null=True, blank=True)
    school = models.ForeignKey("academics.School", on_delete=models.SET_NULL, null=True, blank=True)
🔑 Why a Custom User? If we don't declare a custom User model at the start of a project, changing it later becomes difficult because Django tables have hardcoded references. Doing it upfront allows us to filter all querysets dynamically by role.

Machine Learning

3. Machine Learning Training Pipeline

The ML pipeline joins our database models into a unified dataframe, preprocesses the numeric, categorical, and boolean features, and fits a Random Forest Regressor.

A. Training script

File path: scripts/train_predictor.py

# Query joined tables to build the dataset
results = Result.objects.select_related('student', 'student__user', 'subject').all()
semester_results = {
    (sr.student_id, sr.semester): sr 
    for sr in SemesterResult.objects.all()
}

# Preprocess Pipeline
categorical_cols = [
    'distance_from_home', 'parental_education_level', 'family_income',
    'access_to_resources', 'gender', 'category', 'address_state',
    'subject_type', 'motivation_level', 'parental_involvement', 'peer_influence'
]
numeric_cols = [
    'subject_credits', 'attendance_percentage', 'hours_studied_per_week',
    'sleep_hours_per_night', 'tutoring_sessions', 'physical_activity'
]

# StandardScaler scales numerics; OneHotEncoder maps text options to vectors
preprocessor = ColumnTransformer(
    transformers=[
        ('num', StandardScaler(), numeric_cols + boolean_cols),
        ('cat', OneHotEncoder(handle_unknown='ignore'), categorical_cols)
    ]
)

model = Pipeline(steps=[
    ('preprocessor', preprocessor),
    ('regressor', RandomForestRegressor(n_estimators=100, random_state=42, n_jobs=-1))
])

# Train, evaluate, and pickle serialize
model.fit(X_train, y_train)
with open('ml/student_predictor.pkl', 'wb') as f:
    pickle.dump(model, f)
⚠️ Performance Note: We map n_jobs=-1 to Random Forest to instruct Python to use all CPU cores in parallel for model fitting, dropping training time to seconds.

B. Views logic

File path: app/accounts/views.py

We declare views that render results based on student login context or compile list cards for teachers:

  • my_predictions: Student gets their active predictions along with lifestyle tips (e.g. telling them to increase study hours or sleep if predictions are low).
  • at_risk_students: Staff gets a warnings list of all students under their scope who have any current subjects predicted below 50%.
